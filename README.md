# GSC Analyzer

ابزار تحلیل **Google Search Console** برای سئوکارهای فارسی‌زبان.

داده‌ی سرچ کنسول شما فقط در مرورگر خودتان پردازش و ذخیره می‌شود. این پروژه
بک‌اند ندارد؛ هیچ سطری از داده‌ی شما به هیچ سروری (به‌جز خود گوگل) فرستاده نمی‌شود.

- React + TypeScript + Vite، کاملاً استاتیک
- UI فارسی و RTL با فونت Vazirmatn به‌صورت فایل محلی (بدون CDN)
- ورود با Google Identity Services و دسترسی **فقط‌خواندنی** (`webmasters.readonly`)
- کش داده در IndexedDB تا رفرش صفحه نیاز به دریافت دوباره نداشته باشد

---

## نسخه‌ی آنلاین (ساده‌ترین راه)

اگر فقط می‌خواهید از ابزار **استفاده** کنید و کاری با کد ندارید، لازم نیست چیزی نصب کنید:

1. سایت را باز کنید (لینک در بخش About همین ریپو / تنظیمات Pages).
2. در همان صفحه، **Client ID** اپ گوگل خودتان را وارد کنید. در مرورگر شما ذخیره
   می‌شود و دفعه‌ی بعد دوباره پرسیده نمی‌شود.
3. روی «اتصال به سرچ کنسول» بزنید.

اگر Client ID ندارید، خود صفحه راهنمای ساختش را نشان می‌دهد (دکمه‌ی «Client ID ندارم»)
و آدرس دقیقی را که باید در تنظیمات گوگل مجاز کنید هم چاپ می‌کند.

> نکته‌ی مهم: در **Authorized JavaScript origins** اپ گوگل، باید دقیقاً آدرس همان
> سایتی را اضافه کنید که ابزار را از آن باز می‌کنید. صفحه‌ی راهنما این آدرس را
> نشان می‌دهد تا لازم نباشد خودتان حدس بزنید.

## راه‌اندازی محلی (برای توسعه)

### ۱) نصب

```bash
npm install
```

### ۲) ساخت OAuth Client ID در گوگل

ابزار برای اتصال به سرچ کنسول به یک Client ID نیاز دارد. یک‌بار این مراحل را انجام دهید:

1. به [Google Cloud Console](https://console.cloud.google.com/) بروید و یک پروژه بسازید (یا یکی را انتخاب کنید).
2. **APIs & Services → Library** → دنبال **Google Search Console API** بگردید و **Enable** را بزنید.
3. **APIs & Services → OAuth consent screen**:
   - نوع **External** را انتخاب کنید.
   - نام اپ و ایمیل پشتیبانی را پر کنید.
   - در مرحله‌ی **Scopes** لازم نیست چیزی اضافه کنید (اپ خودش scope را درخواست می‌کند).
   - در مرحله‌ی **Test users**، ایمیل گوگلی که با آن وارد می‌شوید را اضافه کنید.
     اگر این کار را نکنید، هنگام دریافت داده خطای **۴۰۳** می‌گیرید.
4. **APIs & Services → Credentials → Create Credentials → OAuth client ID**:
   - **Application type**: `Web application`
   - در **Authorized JavaScript origins** این دو را اضافه کنید:
     - `http://localhost:5173`
     - `http://127.0.0.1:5173`
   - نیازی به Authorized redirect URI نیست (این اپ از Token Client استفاده می‌کند).
5. Client ID ساخته‌شده را کپی کنید.

> اگر بعداً روی دامنه‌ی دیگری deploy کردید، همان origin را هم به
> **Authorized JavaScript origins** اضافه کنید.

### ۳) تنظیم Client ID

دو راه دارید:

**الف) وارد کردن در خود اپ (ساده‌تر).** هیچ فایلی لازم نیست؛ اپ موقع اجرا از شما
Client ID را می‌پرسد و در مرورگر ذخیره می‌کند.

**ب) از طریق فایل محیطی.** اگر ترجیح می‌دهید در build تثبیت شود:

```bash
cp .env.example .env.local
```

بعد `.env.local` را باز کنید و مقدار را بگذارید:

```
VITE_GOOGLE_CLIENT_ID=123456789-xxxxxxxxxxxx.apps.googleusercontent.com
```

`.env.local` در `.gitignore` است و کامیت نمی‌شود. اگر این مقدار تنظیم باشد، اپ دیگر
از کاربر نمی‌پرسد.

### ۴) اجرا

```bash
npm run dev
```

مرورگر را روی <http://localhost:5173> باز کنید.

> **نکته:** آدرسی که باز می‌کنید باید دقیقاً همانی باشد که در
> Authorized JavaScript origins ثبت کرده‌اید. `localhost` و `127.0.0.1` از نگاه
> گوگل دو origin متفاوت‌اند.

## استفاده

1. روی **«اتصال به سرچ کنسول»** بزنید و با حساب گوگلی که به پراپرتی‌ها دسترسی دارد وارد شوید.
2. از فهرست، پراپرتی مورد نظر را انتخاب کنید. پراپرتی‌های Domain با برچسب `Domain` مشخص شده‌اند.
3. ابزار داده‌ی سه ماه گذشته را می‌گیرد و در سه نما نشان می‌دهد:
   - **صفحه‌محور** (پیش‌فرض) — هر صفحه چقدر کلیک و نمایش گرفته. اعدادش با آمار واقعی
     سایت می‌خواند، چون کلیک‌های کوئری‌های ناشناس هم به صفحه نسبت داده می‌شوند.
   - **کوئری‌محور** — با چه عبارت‌هایی دیده شده‌اید. برای پیدا کردن فرصت خوب است، ولی
     اعدادش کامل نیست (پایین‌تر توضیح داده شده).
   - **فرصت‌ها** — صفحه‌هایی که کمتر از موقعیتشان کلیک می‌گیرند (پایین‌تر).

   برای سایت‌های بزرگ ممکن است چند دقیقه طول بکشد (داده در بسته‌های ۲۵٬۰۰۰ سطری می‌آید).
4. روی عنوان هر ستون بزنید تا مرتب‌سازی عوض شود. با دکمه‌ی **فیلترها** می‌توانید چند
   شرط را با هم ترکیب کنید — چیزی که در خود سرچ کنسول شدنی نیست:
   - **بازه‌ی عددی**: «موقعیت بین ۱ تا ۵»، «نمایش بین ۱۰۰ تا ۵۰۰»
   - **چند شرط هم‌زمان**: «کوئری شامل فلان» و «موقعیت ≤ ۱۰» و «نمایش ≥ ۵۰۰» با هم
   - CTR را بر حسب **درصد** وارد کنید (مثلاً ۳)، نه نسبت اعشاری
   - ارقام فارسی هم قبول است (۱۲٫۵)

   جعبه‌ی جست‌وجوی کنارش هم برای فیلتر سریع متنی روی کوئری و آدرس صفحه است.
5. بالای جدول، **نمودار روند روزانه** کلیک و نمایش را روز به روز نشان می‌دهد و اگر
   افت پایداری پیدا کند، روزی که از آن شروع شده را علامت می‌زند. با نگه داشتن ماوس
   روی نمودار، عدد هر روز را می‌بینید؛ «دیدن اعداد به صورت جدول» همه‌ی روزها را
   به شکل جدول می‌دهد.
6. **«مقایسه با دوره‌ی قبل»** داده‌ی یک بازه‌ی هم‌طول بلافاصله قبل را می‌گیرد و کنار
   اعداد فعلی، تغییر هر کدام را نشان می‌دهد. دو ستون «تغییر کلیک» و «تغییر موقعیت»
   هم به جدول اضافه می‌شود؛ با مرتب‌سازی صعودیِ «تغییر کلیک» بیشترین افت‌ها بالا
   می‌آیند. صفحه‌هایی که ترافیکشان صفر شده هم در فهرست می‌مانند.
7. تب **«فرصت‌ها»** صفحه‌هایی را نشان می‌دهد که کمتر از موقعیتشان کلیک می‌گیرند —
   یعنی رتبه را دارند ولی عنوان و توضیحات کارشان را نمی‌کند. (بخش بعدی)
8. **«به‌روزرسانی داده»** کش را دور می‌زند و داده را دوباره از گوگل می‌گیرد.
   **«پاک کردن داده‌های محلی»** همه‌ی داده‌ی ذخیره‌شده در این مرورگر را حذف می‌کند.

### فرصت‌های بهبود CTR

قاعده‌ی رایجی که در آموزش‌ها می‌بینید — «نمایش بالای ۱۰۰۰ و CTR زیر ۳٪» — عمداً پیاده
نشده، چون هر دو عدد به اندازه‌ی سایت وابسته‌اند: برای یک سایت بزرگ همه‌ی صفحه‌ها رد
می‌شوند و برای یک سایت کوچک فهرست کاملاً خالی می‌ماند. مهم‌تر اینکه CTR بدون موقعیت
بی‌معنی است؛ CTR ۳٪ در رتبه‌ی ۱ فاجعه است و در رتبه‌ی ۱۵ عالی.

به‌جای آن، تب «فرصت‌ها» این کار را می‌کند:

1. **منحنی CTR بر حسب موقعیت را از داده‌ی خود سایت شما می‌سازد.** موقعیت‌ها به بازه‌هایی
   تقسیم می‌شوند و برای هر بازه، میانه‌ی CTR کوئری‌های شما حساب می‌شود. پس معیار قضاوت،
   عدد یک مقاله‌ی انگلیسی نیست؛ زبان و صنعت و شکل نتایج خودتان است.
2. **کوئری‌های برند را از منحنی کنار می‌گذارد.** کوئری برند CTR خیلی بالایی دارد (کاربر
   از قبل دنبال شما بوده) و اگر در منحنی بماند، سقف انتظار کاذب بالا می‌رود و بعد
   *همه‌ی* صفحه‌ها ضعیف به نظر می‌رسند. ابزار از روی دامنه حدس می‌زند و فهرست را نشان
   می‌دهد؛ نام فارسی برند را خودتان اضافه کنید (فاصله و نیم‌فاصله فرقی نمی‌کند). فهرست
   در همین مرورگر ذخیره می‌شود.
3. **به‌جای فیلتر، رتبه‌بندی می‌کند** — با «کلیک از دست رفته» = نمایش × (CTR انتظاری −
   CTR فعلی). این عدد حجم را در خودش دارد، پس آستانه‌ی نمایش لازم نیست: صفحه‌ی پرنمایش
   با فاصله‌ی کم، بالاتر از صفحه‌ی کم‌نمایش با فاصله‌ی زیاد می‌آید. فهرست هم هیچ‌وقت خالی
   نمی‌شود.
4. **می‌گوید چقدر می‌شود به هر سطر اعتماد کرد.** ستون «اطمینان» از فاصله‌ی کلیک واقعی تا
   کلیک انتظاری بر حسب انحراف معیار می‌آید، نه از یک آستانه‌ی دلبخواهی روی نمایش.
   سطرهای «کم» به‌طور پیش‌فرض پنهان‌اند و با یک تیک برمی‌گردند.

با کلیک روی هر صفحه، عبارت‌هایی که با آن‌ها دیده شده (پرنمایش‌ترین‌ها بالا) باز می‌شود —
همان چیزی که عنوان و توضیحات صفحه باید جوابش را بدهد.

فهرست یک **اولویت‌بندی** است نه حکم: نتایج ویژه‌ی گوگل، تبلیغ بالای صفحه، و کوئری‌های
اطلاعاتی که کاربر جوابش را در خود SERP می‌گیرد هم CTR را زیر انتظار می‌آورند.

### بازه‌ی زمانی

پایان بازه همیشه **امروز منهای ۳ روز** است، چون داده‌ی سرچ کنسول ۲ تا ۳ روز تأخیر
دارد و روزهای آخر ناقص‌اند.

طول بازه را از نوار بالای جدول انتخاب می‌کنید: **۷ روز، ۲۸ روز، ۳ ماه، ۶ ماه،
۱۲ ماه**. این‌ها عیناً همان گزینه‌های صفحه‌ی Performance سرچ کنسول‌اند تا اگر اعداد
را با گوگل چک کردید، بخواند. (در سرچ کنسول «ماهانه» یعنی ۲۸ روز، نه ۳۰ روز.)

بازه‌ای که یک‌بار دیده شده کش می‌شود، پس رفت‌وبرگشت بین بازه‌ها دوباره دانلود نمی‌خواهد.
دوره‌ی مقایسه هم همیشه هم‌طول بازه‌ی انتخابی و بلافاصله قبل از آن است.

### چند نکته که خواندن اعداد را عوض می‌کند

- **میانگین موقعیت وزنی است.** با وزن Impression حساب می‌شود، نه میانگین ساده‌ی ستون موقعیت.
- **در نمای کوئری‌محور، جمع کلیک‌ها با آمار کل سایت نمی‌خواند.** بخش بزرگی از کلیک‌ها
  (اغلب بیش از ۹۰٪) از کوئری‌هایی می‌آید که گوگل برای حفظ حریم خصوصی کاربران گزارش
  نمی‌کند. بالای هر جدول، ابزار آمار کل سایت را کنار جمع همان جدول با درصد پوشش نشان
  می‌دهد تا معلوم باشد چقدر از داده دیده نمی‌شود. برای اندازه‌گیری ترافیک از نمای
  صفحه‌محور استفاده کنید، نه کوئری‌محور.
- **CTR درصد است.** API عدد اعشاری می‌دهد (`0.048`) و اینجا به‌شکل `۴٫۸۰٪` نمایش داده می‌شود.

## خطاهای رایج

| خطا | معنی | راه حل |
| --- | --- | --- |
| پنجره‌ی ورود باز می‌شود ولی خطا می‌دهد | آدرس سایت در Authorized JavaScript origins ثبت نشده | آدرسی که صفحه‌ی راهنما نشان می‌دهد را عیناً در تنظیمات اپ گوگل اضافه کنید |
| ۴۰۳ | ایمیل شما در Test users نیست، یا Search Console API فعال نشده | مرحله‌های ۲ و ۳ بالا را دوباره چک کنید |
| ۴۲۹ | سقف نرخ درخواست گوگل | ابزار خودش چند بار با تأخیر تلاش می‌کند؛ اگر نشد چند دقیقه صبر کنید |
| «نشست شما تمام شد» | توکن یک‌ساعته منقضی شده | روی «ورود مجدد به گوگل» بزنید؛ داده‌ی کش‌شده از بین نمی‌رود |
| «اتصال به گوگل برقرار نشد» | دسترسی شبکه به سرویس‌های گوگل | اتصال خود به `googleapis.com` و `accounts.google.com` را بررسی کنید |
| پنجره‌ی ورود باز نمی‌شود | مسدودکننده‌ی پاپ‌آپ | پاپ‌آپ را برای این سایت مجاز کنید |

## build و انتشار

```bash
npm run build     # خروجی استاتیک در dist/
npm run preview   # پیش‌نمایش محلی همان خروجی
```

با هر push روی `main`، گیت‌هاب اکشن (`.github/workflows/deploy.yml`) پروژه را build
می‌کند و روی **GitHub Pages** می‌گذارد. محتوای `dist/` را روی هر هاست استاتیک دیگری
هم می‌شود گذاشت.

یادتان باشد origin هر جایی که سایت را بالا می‌آورید به
**Authorized JavaScript origins** اپ گوگل اضافه شود.
